# Мультиязычность — implementation notes

> Статус: реализовано. В приложении есть 15 локалей с переводами интерфейса и
> Help. Актуальный список задаёт `internal/config.AllLanguages`, а словари
> находятся в `internal/i18n/assets`. Этот файл сохраняет историю и требования
> к переводу; при расхождении ориентируйтесь на реализацию.

Шрифт содержит глифы для китайского (включая традиционные иероглифы),
вьетнамского, тайского и бирманского. Для бирманского языка перевода UI нет;
арабский язык и RTL-направление также не поддерживаются.

## Цели

- Перевести весь интерфейс, справку и пользовательские уведомления.
- Хранить весь пользовательский текст в assets, а не в Go-коде.
- Переключать язык в Settings без перезапуска приложения.
- Сохранить компактность интерфейса на экранах портативных устройств.
- Не связывать доменную логику с текстами и не превращать локализацию в
  глобальное изменяемое состояние.
- Сделать добавление следующего языка механической задачей: файл перевода,
  проверка и визуальное тестирование.

В поставку входят `en`, `ru`, `zh-Hans`, `zh-Hant`, `ja`, `ko`, `vi`, `th`,
`id`, `ms`, `pt-BR`, `es`, `de`, `fr` и `tr`. Английский остаётся языком по умолчанию,
поэтому существующая установка после обновления визуально не меняется. Выбор
языка сохраняется в `settings.json`.

## Что переводим

Переводятся:

- названия страниц, секций, настроек и их значений;
- контекстные подсказки нижней панели;
- статусы, подтверждения и пользовательские уведомления;
- Help, включая названия тем и пояснения;
- динамические подписи и счётчики, создаваемые приложением.

Не переводятся:

- имена файлов, каталогов, треков, исполнителей и пресетов;
- названия форматов, устройств и провайдеров (`Modland`, `ModArchive`);
- URL, пути, технические характеристики и тексты лицензий;
- структурированные логи и внутренние ошибки разработчика;
- физические обозначения кнопок (`A`, `B`, `Enter`, `L1/R1`). Переводится
  только действие рядом с кнопкой: `Open`, `Back`, `Play` и т. п.

Символ `/` у каталогов и пунктов с подменю является частью структуры UI, а не
перевода. Он добавляется после локализации тем же существующим presentation-
кодом.

## Владение и зависимости

Добавить независимый пакет `internal/i18n`. Он является единственным владельцем
словарей, ключей сообщений, выбора fallback и форматирования множественного
числа. Пакет не зависит от `ui`, `app`, `player` или `config`.

`internal/config` владеет сохранённым выбором языка. `internal/ui` владеет
моментом перевода экранного текста и инвалидирует текстуры после смены языка.
`internal/app` передаёт в UI семантическое событие или ключ сообщения с
аргументами, но не собирает локализованную строку заранее.

Направление зависимостей:

```text
config.Language ──> app wiring ──> i18n.Catalog ──> ui presentation
                                      ↑
                              message ID + arguments
```

В таблицу владельцев `docs/ARCHITECTURE.md` при реализации добавляется строка:

| Понятие | Единственный владелец | Остальные проекции |
|---|---|---|
| UI translations | `internal/i18n` | `internal/config` language choice, UI/help/notifications |

## Формат и API

Для KISS-подхода не добавлять внешнюю библиотеку локализации. **Все тексты,
которые может увидеть пользователь, хранятся в UTF-8 assets и встраиваются
через `go:embed`.** В Go остаются только стабильные ключи, аргументы шаблонов и
правила выбора текста:

```text
internal/i18n/
  catalog.go
  key.go
  plural.go
  assets/en.json
  assets/<language>.json
  assets/<language>-help.json
```

Ключи семантические и стабильные, а не равны английскому тексту:

```json
{
  "page.library": "Library",
  "action.pause": "Pause",
  "settings.cache.lifetime": "Lifetime"
}
```

Минимальный API:

```go
type Language string

const (
    English Language = "en"
    Russian Language = "ru"
)

type Catalog struct { /* immutable after construction */ }

func Load(language Language) (Catalog, error)
func (c Catalog) Text(key Key) string
func (c Catalog) Format(key Key, args ...any) string
func (c Catalog) Plural(key Key, n int, args ...any) string
```

`Key` должен быть именованным типом с константами. Это позволяет искать
использования через `rg`, не разносить строковые литералы по UI и проверять
полноту каталогов тестом. Каталог неизменяем после загрузки и передаётся явно;
глобальная текущая локаль не вводится.

Locale asset содержит все категории текста в одном проверяемом дереве:

```json
{
  "pages": {},
  "actions": {},
  "settings": {},
  "library": {},
  "presets": {},
  "notifications": {},
  "errors": {},
  "help": {}
}
```

Физическое деление большого locale на несколько embedded JSON-файлов допустимо
позже, но публично это остаётся одним `Catalog`. Нельзя оставлять английскую
строку в Go как «временный fallback»: fallback также берётся из `assets/en.json`.
Исключения — только непереводимые данные из раздела «Что переводим» и технические
строки логов/errors, которые никогда не показываются пользователю напрямую.

Fallback: запрошенный язык → английский. Отсутствующий ключ является ошибкой
при загрузке/в тестах; во время рендера безопасно возвращается английская строка,
чтобы единичная ошибка перевода не ломала UI. Неизвестное значение языка в
`settings.json`, как и другие неизвестные enum-значения, остаётся ошибкой
валидации и не маскируется default-настройкой.

## Настройка языка

В `config.UISettings` добавить `Language` с JSON-полем `language`. Реализовать
тот же контракт, что у остальных enum-настроек: стабильное строковое значение,
`MarshalJSON`, `UnmarshalJSON`, `Validate` и `AllLanguages`.

В Settings добавить однословный пункт `Language` в секцию Appearance со
значениями `English` и `Русский`. Самоназвания языков не переводить: пользователь
должен суметь вернуть понятный язык даже после случайного переключения.

После применения значения app сохраняет settings, загружает каталог и передаёт
его Overlay. Overlay инвалидирует все зависящие от текста ресурсы:

- page indicator;
- Settings rows и description;
- Help columns и wrapping;
- action hints;
- breadcrumb только там, где присутствует системная подпись;
- текущую текстовую notification, если она построена из message ID.

GL-ресурсы удаляются и пересоздаются лениво существующими механизмами dirty-
флагов на главном потоке. Смена языка не запускает сканирование библиотеки и не
трогает playback.

## Отделение отображения от сохранённых значений

Методы `String()` у config enum сейчас используются для UI, а некоторые
строковые представления связаны с сериализацией и тестами. Их нельзя делать
зависимыми от текущего языка.

При реализации:

- оставить JSON tokens и внутренние `String()` стабильными;
- формировать значения Settings через явное сопоставление enum → i18n key;
- числовые и технические значения (`1 GB`, `1280x720`, `75%`, `25 FPS`, `20 FPS`)
  форматировать отдельно от переводимого шаблона;
- не хранить переведённые подписи в `SettingRow` дольше текущего каталога;
- не сравнивать выбранное значение по переведённой строке — индекс и enum
  остаются источником истины.

Это устраняет зависимость поведения и persisted config от языка интерфейса.

## Help

Текущий единый `internal/ui/assets/help.json` перенести в секцию `help` каждого
locale asset, сохранив одинаковую структуру и стабильные `id`. Таким образом,
Help подчиняется тому же правилу, что и остальные тексты, и не образует второй
независимый механизм локализации. Лицензии по-прежнему хранятся отдельно и
подставляются без перевода.

На старте загружается только выбранный Help-каталог. При смене языка состояние
навигации сохраняется по topic/entry ID, а не по позиции или отображаемому
заголовку. Если на первом этапе дочерние элементы ещё не имеют ID, добавить их
до перевода Help; индекс допустим только как временная реализация при строгом
тесте равенства деревьев.

Тест должен сравнивать языки и проверять:

- одинаковые ID и форму дерева;
- наличие всех обязательных строк;
- корректность ссылок на лицензии;
- отсутствие пустых заголовков;
- сохранение `/` только у узлов с дочерними элементами.

## Динамический текст и множественное число

Не собирать предложения конкатенацией локализованных фрагментов. В словаре
хранится целый шаблон, например `cache.removed`, а код передаёт количество и
размер.

Для английского, немецкого и испанского достаточно форм `one/other`; для русского нужны
`one/few/many/other`. Небольшую функцию выбора формы реализовать внутри i18n и
покрыть граничными числами `0, 1, 2, 4, 5, 11, 21, 22, 25, 101`. Полноценные
Китайский, японский, корейский, индонезийский и турецкий используют `other`;
французский использует `one` для 0 и 1. Полная ICU-зависимость пока не нужна.

Системные ошибки разделяются на локализованное объяснение и необязательную
техническую деталь. Например, UI показывает перевод `Could not delete file`,
а исходный `error` можно вывести следующей строкой или записать в лог. Не
следует пытаться переводить тексты ошибок сторонних библиотек.

## Шрифт и компоновка

Базовые диапазоны задаются в `font_ranges.json`, а `subset-font.sh` дополнительно
собирает точный набор символов из всех locale и Help assets. В базовый набор
включены CJK, хирагана/катакана, хангыль, тайская и бирманская письменности,
чтобы добавление следующей локали не требовало срочной пересборки шрифта.
Арабские диапазоны намеренно не
добавляются: для них требуется отдельная поддержка RTL и shaping.

Перевод может быть длиннее английского текста. Поэтому:

- сохранить однословные названия пунктов там, где это возможно;
- использовать существующие wrapping и marquee, не уменьшать общий шрифт;
- проверить 640×480 как минимальный дизайн-размер;
- footer продолжает отбрасывать подсказки низкого приоритета при нехватке места;
- не обрезать подтверждения и критические ошибки без доступного scrolling.

## Этапы реализации

### 1. Инфраструктура

1. Добавить `config.Language`, default `en`, JSON validation и storage tests.
2. Добавить `internal/i18n`, typed keys, embedded catalogs и fallback.
3. Добавить тест равенства наборов ключей, шаблонов и placeholder-аргументов.
4. Добавить проверку glyph coverage словарей и Help относительно embedded font.
5. Добавить статическую проверку, запрещающую новые пользовательские строковые
   литералы вне locale assets; небольшой allowlist оставить для logs, format
   tokens, путей, URL и технических единиц.

### 2. Статический UI

1. Перевести page indicator, Settings labels/values/descriptions и footer.
2. Добавить настройку `Language` и runtime-инвалидацию текстур.
3. Перевести системные подписи Library и Presets, не затрагивая пользовательские
   имена.
4. Удалить все пользовательские строковые литералы из render/input/config
   presentation-кода. Даже английский текст берётся из locale asset.

### 3. Help

1. Ввести стабильные ID для всех навигационных узлов.
2. Хранить отдельный Help для каждой локали и валидировать одинаковую структуру.
3. Сохранять текущий раздел при переключении языка и перестраивать wrapping.

### 4. Уведомления и ошибки

1. Заменить готовые строки между app и UI на message ID + typed arguments либо
   на семантические методы Overlay.
2. Перевести подтверждение удаления, network/cache/playback статусы и fallback-
   состояния.
3. Оставить технические ошибки и slog-сообщения на английском.

### 5. Завершение

1. Проверить все страницы на 640×480 с клавиатурой и геймпадом.
2. Проверить смену языка во всех состояниях: modal, Help submenu, Settings edit,
   playback/loading и offline catalogs.
3. Обновить `docs/ARCHITECTURE.md`, `docs/UI-PLAN.md`, README и packaging inputs.
4. Выполнить `scripts/dtest.sh test`, `scripts/dtest.sh lint` и `make dist`.

## Тестовый контракт

Обязательные unit tests:

- round trip и rejection неизвестного `config.Language`;
- default language для отсутствующего файла настроек;
- полное совпадение ключей всех каталогов с `en`;
- совпадение placeholders у каждого перевода;
- отсутствие пользовательских текстов в Go-коде вне явно проверяемого allowlist;
- plural-правила всех поддерживаемых языковых групп;
- Settings не сравнивает localized labels для выбора enum;
- runtime switch сохраняет page, focus, cursor и playback state;
- все зависящие от текста dirty-флаги выставлены после switch;
- Help сохраняет выбранные IDs и структуру submenu;
- action hints показывают корректный `Play`/`Pause` на обоих языках;
- пользовательские имена файлов, каталогов и пресетов не переводятся;
- glyph coverage всех каталогов и Help.

Строковые snapshot-тесты использовать только для небольших стабильных
компонентов. Основные тесты должны проверять ключи, структуру и состояние, чтобы
правка формулировки перевода не требовала массового обновления fixtures.

## Критерии готовности

- В Settings можно переключить любую поддерживаемую локаль без перезапуска.
- После перезапуска выбранный язык восстанавливается, а повреждённое или
  неизвестное значение настроек явно считается ошибкой.
- На выбранном языке нет смешанного UI, кроме перечисленных непереводимых данных
  и технических деталей ошибок.
- Весь видимый текст поддерживаемых языков находится в locale assets; Go-код не содержит
  скрытого набора английских fallback-строк.
- Смена языка не меняет навигацию, очередь, playback и содержимое каталогов.
- На 640×480 нет наложений; важный текст доступен полностью.
- Добавление тестовой третьей локали не требует изменений в UI-коде.
- Полные test/lint/dist проверки проходят.

## Осознанно не входит в первую версию

- автоматическое определение системного языка;
- загрузка переводов из сети или пользовательские language packs;
- перевод метаданных, preset names и лицензий;
- RTL-языки и сложная shaping-типографика;
- regional formatting дат и чисел;
- внешняя ICU/CLDR-зависимость.

Эти ограничения сохраняют реализацию небольшой. Автовыбор системного языка
можно добавить позже как значение `auto`, когда появится единый платформенный
API для Linux/PortMaster и Android.
