# UI Улучшения — План

> Статус: рабочая спецификация актуальной UI-модели. Старые решения, которые
> противоречат текущей реализации, не являются контрактом и должны быть
> удалены или явно помечены как исторические.

## Источник истины

- Поведение навигации и фокус-машины фиксируется в этом документе и
  проверяется тестами `internal/ui/overlay_test.go`.
- Файловые операции принадлежат приложению и filesystem-сервисам; UI только
  формирует команду и показывает результат.
- Конфигурация принадлежит `internal/config`; сохранение и загрузка проходят
  через единый `Settings.Validate`.
- `player.Library` отвечает за локальный индекс, а playback state — за порядок
  воспроизведения. Remote-каталоги не являются локальной файловой системой.
- Неожиданное состояние должно возвращаться как ошибка или явно отображаться
  как неизвестное. Пустой список не означает ошибку чтения.

Нормативными считаются только решения со статусом `ПРИНЯТО` или `В РАБОТЕ`.
Идеи, отклонённые решения и завершённые исторические этапы не должны
использоваться как требования к новой реализации.

GL-оверлей поверх projectM (SDL2): Library/Settings/Presets, 2-панельный браузер,
Unifont (моно, BMP-only), геймпад + клавиатура.

### Компактный header (ПРИНЯТО)

При открытом UI header целиком принадлежит названиям страниц: они рисуются
основным кеглем и центрируются относительно всей ширины экрана. Stats в меню не
показываются, чтобы телеметрия не пересекалась с навигацией на узких экранах.
На страницах Library и Presets под навигацией резервируется вторая компактная
строка для breadcrumb текущего пути; Settings и Help сохраняют однострочный
header.
При скрытом UI полная строка stats остаётся доступна как отдельный HUD и
рисуется кеглем 75% (не меньше 10 px), поскольку это вторичная диагностическая
информация поверх visualizer.
Все пиксельные размеры header и служебных элементов вычисляются через единую
шкалу от текущей высоты экрана, где 480p задаёт только дизайн-референс, а не
фиксированный размер окна.

Правая панель Presets показывает структурные метрики (`Shapes`, `Waves`,
`Equations`), число уникальных внешних `Textures` и измеренный `Preview FPS`.
Производная шкала сложности не показывается: фактический preview FPS лучше
отражает стоимость preset на текущем устройстве. Автор не извлекается из имени
файла: стандартный `.milk` не предоставляет надёжного обязательного поля автора.

## Этап 2 — NC-панель (LOCAL-ONLY)

**Главное решение (scope):** NC-режим — только для локальной ФС. Modland/
ModArchive остаются в текущей album-oriented навигации со старым
preview/info справа, без кнопок, без Delete, без artwork. Это убирает
неоднозначности: remote не скачан, ModArchive грузится асинхронно,
виртуальные альбомы, URL-плейлисты — всё вне NC-модели.

### 2.1 Модель (решено)
- **Левая панель** — браузер реальной ФС: обход `os.ReadDir`, каталоги + файлы,
  «..» в начале, drill-down. Не использовать `player.Album` как навигационную
  сущность — альбом для UI = просто каталог с файлами. `player.Album` остаётся
  для плейбэка/учёта.
- **Какие файлы показываются (решено):** каталоги; только поддерживаемые
  аудиофайлы; служебные `.gsa_meta.json`, artwork и прочие скрываются.
  Пустой каталог = нет поддерживаемых аудиофайлов и подкаталогов. Нет
  состояний «неактивный файл».
- **Правая панель** — инфо выбранного элемента + кнопки **Play ▸** / **Delete ✕**
  (псевдо-кнопки текстом). Для remote-элементов — старый preview/info, кнопок нет.
- **Enter** на каталоге = вход (список файлов); **Enter** на файле = play.
- Drill-in = Enter или A (SDL B = Select, `input.go:174`). Вверх = Backspace или
  B (SDL A = Back, `input.go:176`) или «..».

### 2.1.1 Режимы источников (дискриминатор, решено)
Корень Library — виртуальный root источников `/`, а не физический `baseDir`.
`music/` отображает локальную файловую систему, а `modland/` и `modarchive/`
открывают удалённые каталоги. Будущие `radio/` и `microphone` добавляются как
соседние источники, не как каталоги внутри локальной музыки.

Нужен явный типизированный дискриминатор (как `UIPage`/`navEntryKind`), а не
int:
```go
type sourceKind int
const (
    sourceMusic sourceKind = iota
    sourceModland
    sourceModArchive
    sourceRadio
    sourceMicrophone
)
```
чтобы источник не смешивался с `focusPanel`, физическим путём или provider
навигацией.
- `sourceRoot` показывает строки источников: `music/`, `modland/`,
  `modarchive/`; недоступный remote source отображается disabled или скрывается
  по существующему правилу connectivity.
- `sourceMusic` использует NC-стек путей и `os.ReadDir`; `player.Library` не
  участвует в навигации — только в плейбэке и playing state.
- `sourceModland` и `sourceModArchive` используют текущую album/provider-модель
  (`navStack`, `SetAlbums`/`SetTrackInfos`, `overlayPresenter`).
- `sourceRadio` в будущем показывает станции, `sourceMicrophone` — действие и
  состояние захвата; эти источники не обязаны притворяться каталогами.
- Вход в UI: локальный трек открывает `/music` в каталоге трека; remote-трек
  открывает соответствующий provider deep-link; без плейбэка открывается `/` или
  последний выбранный источник по отдельному решению UX.
- `Back` из локального или provider root возвращает в `/`; `Back` из `/` закрывает
  UI. Переход между источниками не должен сбрасывать сохранённый NC path.
- Удаление разрешено только внутри `sourceMusic`; virtual root и remote sources
  не являются целями `Delete`.

### 2.2 Фокус-машина (решено)
Фокус: левая панель → [Play] → [Delete], циклично Left/Right.
- Right: левая → Play → Delete (по одному шагу).
- Left: Delete → Play → левая.
- Backspace/B: сразу на левую из любого состояния.
- Up/Down: на левой — навигация по списку; на правой — переключение Play↔Delete.
- Back во время confirm: отмена, фокус остаётся на Delete.
- Play при выбранном каталоге: разрешено (рекурсивный плейлист).
- Пустой каталог: правая панель доступна, Play активна (плейлист пуст — без
  эффекта), Delete работает.
- После Delete: фокус на левую, уровень перестроен, курсор клампится, инфо
  обновляется.
- После Play: фокус не меняется, UI остаётся открытым.
- Delete на remote: кнопка не показывается.

### 2.3 Play файла/каталога (решено)
UI формирует команду, приложение владеет плейбэком — **app-level action
`PlayDirectory(path)`**, UI не читает Library напрямую (паттерн `actions.go`).
- Порядок обхода: сортировка после обхода (lexical по пути).
- Только поддерживаемые расширения (существующий список), `.gsa_meta.json`
  исключается.
- Недоступные файлы/подкаталоги: listing получает статус `Partial` или
  `Failed`; playback не меняет текущий плейлист, а UI явно показывает
  неопределённость вместо пустого результата.
- Пустой результат: плейлист НЕ меняется, notifier «нет воспроизводимых
  файлов».
- Непустой: заменяет текущий плейлист (через `playbackState.setPlaylist`).
- **Shuffle к плейлисту НЕ применяется** — `advance()` (`playback_state.go:
  144-158`) идёт по плейлисту линейно, shuffle только при `len(playlist)==0`
  (строка 168). Repeat применяется существующей логикой. Shuffled playlists —
  отдельная задача playback-state, не UI.
- v1: синхронный walk (stat-only), UI заблокирован на время обхода, отмены нет.
  Если на больших деревьях заметны тормоза — отдельная задача: worker +
  индикатор.

### 2.4 Delete — отдельный безопасный сервис (до UI-кнопки)
UI формирует команду; проверка и удаление — в сервисе, не в UI.

**Контракт API (формализован):**
- Граница: `baseDir` сам может быть symlink — разрешить один раз при старте
  (`Clean` + `EvalSymlinks`), resolved base = граница доступа.
- Запрещено: пустой путь; `.` после Clean; путь == baseDir; путь вне resolved
  base (`Clean` + `EvalSymlinks` цели, оба должны быть внутри).
- **Symlink: запрещены ВСЕ** (и ведущие внутрь, и наружу) в v1 — проще
  объяснить пользователю и доказать тестами; ослабление позже при реальной
  необходимости. Никогда не удалять целевой каталог вместо ссылки.
- TOCTOU: `EvalSymlinks` не защищает от гонки проверка→`RemoveAll`. Приемлемо
  для локального однопользовательского приложения; API не обещает защиту от
  конкурентного злоумышленника.
- Удаление корня библиотеки запрещено. `.gsa_meta.json` не существует как
  отдельный пользовательский объект (удаление каталога включает его).
- Подтверждение при большом числе файлов (порог — параметр).
- Если играющий трек внутри удаляемого — остановить плейбэк.

**Порядок с учётом race (решено):** сначала удаление; **только при успехе** —
если играющий трек == удаляемому пути или внутри каталога, остановить плейбэк;
очистить плейлист, если содержит удалённые пути; рескан библиотеки. При
неудачном удалении playback state не трогаем — нет частично очищенного
состояния.

**Метадата (конкретно):** `.gsa_meta.json` внутри удаляемого дерева удаляется
вместе с деревом. После успешного удаления — рескан `player.Library`
существующим scan (обновляет индексы; курсор overlay клампится — уже в 2.2).
При удалении отдельных файлов — обновить/удалить `.gsa_meta.json`
родительского каталога.

**Ошибки:** permission errors → не-модальный показ (существующий notifier).

**Тесты:** temp dir, вложенные папки, symlink внутрь/наружу baseDir, путь вне
baseDir, пустой путь, путь == baseDir, удаление играющего файла.

### 2.5 Artwork — асинхронный worker
- Декод + масштаб — вне UI-лупа (goroutine), аплоад текстуры — в основном
  GL-контексте (паттерн `modArchiveResults` chan + closeCh уже есть).
- Stale-guard: результат не заменяет арт другого выбранного каталога (сверка
  пути в момент применения).
- Лимит размера исходника (~2MP), кэш с eviction (LRU, ~32), инвалидация при
  удалении каталога.
- «Нет арта» ≠ «грузится» (плейсхолдер).
- Расширения `.jpg/.jpeg/.png` case-insensitive; приоритет `album.jpg` →
  `album.png`.

### 2.6 Хлебные крошки
- В `navLevel` добавить `label string`, записывать при `pushLevel`
  (`overlay_nav.go:66-70`) — не выводить из entries.
- Виртуальный root отображать как `/` или отдельный root marker, но не как
  физический путь `baseDir`; локальный источник начинается с `music/`.
- Показывать последние 2-3 компонента пути; remote URL сокращать (логика
  `displayTrackPath` есть); breadcrumbs не интерактивные; leaf album учитывается
  при входе в него.
- Иконка источника является presentation-слоем и не входит в сравниваемый
  navigation label: внутреннее состояние хранит `sourceKind`.

### 2.7 Icon font для источников
Добавить второй монохромный шрифт для иконок, не заменяя Unifont. Unifont
остаётся основным шрифтом текста, кириллицы и UI. Новый font face используется
только для source markers и, при необходимости, будущих action markers.

**Ограничение subset:** в приложение попадают только glyphs, реально
используемые UI. Нельзя копировать полный icon font или Unicode-блок целиком.
Создать отдельный manifest, например `internal/ui/icon_ranges.json`, со списком
точных codepoints. Для первой версии нужны только иконки:
- local filesystem / computer;
- network / remote catalog;
- radio;
- microphone;
- optional root/home marker, если он нужен отдельно от `/`.

**Сборка и хранение:**
- выбрать монохромный font с лицензией, совместимой с дистрибуцией проекта;
- зафиксировать версию и источник полного font в `Dockerfile.builder`;
- subset-ить полный font через `fontTools.subset` по `icon_ranges.json`;
- сохранить результат в `internal/ui/assets/` и подключить через `go:embed`;
- добавить лицензию и attribution в `portmaster/licenses/`;
- не включать цветные emoji tables, variation-selector варианты и неиспользуемые
  glyphs без отдельной необходимости.

**Рендеринг:**
- добавить отдельный `iconFace` с тем же lifecycle, что и основной `face`;
- закрывать его в `Overlay.Close` и пересоздавать при изменении размера;
- измерять icon glyphs через `iconFace`, а текст — через `face`;
- вынести генерацию icon texture в отдельный helper, не смешивая icon codepoint
  с navigation labels;
- проверить baseline, размер, контраст, clipping и fallback при отсутствии glyph.

**Проверки:**
- тест/скрипт проверяет, что каждый codepoint из manifest есть в итоговом OTF;
- тест/скрипт проверяет отсутствие лишних codepoints сверх разрешённых диапазонов;
- `make test`, `make lint`, `make dist` проходят с чистым и повторяемым font build;
- визуально проверить root/source list на целевых разрешениях и на ARM-сборке.
