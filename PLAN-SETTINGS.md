# План: меню настроек

## Цель

Добавить в существующий UI отдельный экран настроек графики. Экран должен выглядеть и работать как списки альбомов и треков:

- слева находятся названия настроек;
- справа отображается значение настройки, выбранное для строки;
- активная строка и активное значение подсвечиваются тем же цветом, который используется для текущего играющего трека;
- во время открытия меню визуализация и воспроизведение продолжаются;
- настройки применяются сразу после подтверждения и сохраняются между запусками.

Первый этап включает только ручной выбор качества. Автоматический режим масштабирования оставить для отдельной задачи.

Работу выполнить вместе с лёгким структурным рефакторингом существующего UI. Цель рефакторинга — устранить дублирование и неименованные значения в затронутом коде, сохранив текущее поведение библиотеки, плеера и overlay.

Принципы реализации:

- **DRY:** общие панели, строки, подсветка, layout и форматирование должны иметь один источник истины;
- **KISS:** использовать небольшие типы и функции вместо универсального UI-фреймворка;
- **SOLID:** отделить модель настроек, навигацию, вычисление разрешений, сохранение и OpenGL-отрисовку;
- **минимальный рефакторинг:** не менять несвязанные части приложения и не переносить код в абстракции, которые не нужны экрану настроек;
- **совместимость:** сначала сохранить текущее поведение Albums/Tracks, затем подключить общий код к настройкам.

## Макет

```text
+--------------------------------------------------------------+
| FPS: 60                                                      |
|                                                              |
|  +--------------------------+  +----------------------------+|
|  | Render resolution        |  | 320x240                   ||
|  | Upscale filter           |  | Pixel                     ||
|  |                          |  |                            ||
|  +--------------------------+  +----------------------------+|
|                                                              |
|  progress bar                         01:23 / 04:56           |
|  play       next       previous              44.1kHz stereo  |
+--------------------------------------------------------------+
```

Левая и правая панели имеют те же размеры, фон, рамку фокуса, отступы, шрифт и поведение прокрутки, что и панели Albums/Tracks. Правая панель не является отдельным списком: она показывает значение строки, на которой находится курсор слева.

## Настройки первого этапа

### Render resolution

Значения формируются от фактического размера окна или framebuffer и показываются в пикселях:

```text
640x480
480x360
400x300
320x240
256x192
240x180
160x120
128x96
80x60
```

Список не должен быть зашитым для одного устройства. Для каждого базового разрешения приложение вычисляет кандидаты из фиксированного набора масштабов:

```text
1.0, 0.75, 0.625, 0.5, 0.4, 0.375, 0.25, 0.2, 0.125
```

Кандидат добавляется только если ширина и высота после масштабирования являются целыми числами. Дубликаты удаляются. При необходимости варианты с меньшей стороной меньше 80 пикселей можно скрывать из обычного меню; `80x60` оставить доступным как самый производительный режим, если он получается целым.

Внутреннее значение настройки должно хранить не текст, а размер или стабильный идентификатор варианта. Предпочтительный вариант:

```go
type RenderResolution struct {
    Width  int
    Height int
}
```

При изменении размера окна список доступных вариантов пересчитывается. Сохранённое разрешение восстанавливается, если оно всё ещё доступно; иначе выбирается ближайший допустимый вариант.

### Upscale filter

В обычном меню показывать понятные названия, а не OpenGL-константы:

```text
Smooth  -> GL_LINEAR
Pixel   -> GL_NEAREST
```

`GL_LINEAR` внутри `BlurTexture.cpp` не относится к этой настройке. Это внутренний sampler projectM для blur-проходов и он остаётся линейным. Настройка меняет только sampler финального fullscreen upscale в `internal/projectm/rendertarget.go`.

### Будущий Auto

`Auto` не включать в первый этап. Позже он должен быть отдельным вариантом `Render resolution`, который меняет только масштаб рендера по производительности. Выбранный upscale filter при этом сохраняется.

## Навигация

Использовать существующие действия input и модель двух панелей:

- `Up/Down` — перемещение по названиям настроек;
- `Left/Right` — переход между левой и правой панелью;
- `Select` — вход в редактирование значения или подтверждение;
- `Left/Right` внутри значения — выбор предыдущего/следующего варианта;
- `Select` — применить значение и выйти из редактирования;
- `Back` — отменить незавершённый выбор или выйти из настроек;
- `ToggleUI` — закрыть UI, сохранив уже подтверждённые изменения.

При входе в меню курсор устанавливается на первую настройку, а справа показывается её текущее значение. Пока пользователь редактирует значение, оно должно отличаться от подтверждённого состояния только визуально; применение выполняется на `Select`.

## Подсветка

Нужно ввести одну общую цветовую константу или тему, используемую всеми списками:

- текущий играющий трек;
- активная строка настроек;
- выбранное значение настройки;
- при необходимости активный пункт альбомов/треков.

Цвет должен совпадать визуально, а не только быть похожим по смыслу. Не дублировать RGB-значения в `renderUI`, `rebuildAlbumsTex`, `rebuildTracksTex` и новом рендерере настроек.

Рекомендуемая семантика:

- цвет играющего трека — постоянный accent color;
- рамка панели — нейтральная белая/серая подсветка фокуса;
- активная строка — accent color с прозрачностью;
- обычный текст — белый;
- неактивные значения — приглушённый серый.

Сейчас играющий трек обозначается символом, а курсор — полупрозрачным прямоугольником. При реализации настроек сначала вынести accent color в общий примитив, затем использовать его для текущего трека и активного значения.

## Архитектура переиспользования

### Общая модель строки

Добавить переиспользуемую модель списка двух панелей, не привязывая её к альбомам:

```go
type SettingRow struct {
    Label  string
    Value  string
    Values []string
    Index  int
}
```

Для отрисовки можно использовать общий компонент списка с двумя колонками:

```go
type ListPanel struct {
    Rows       []string
    Cursor     int
    Focused    bool
    Scroll     int
    AccentRows map[int]bool
}
```

Не переносить в этот компонент логику выбора альбома, воспроизведения или сохранения. Компонент отвечает только за layout, курсор, прокрутку, фон, рамку и текст.

### Overlay

Расширить `Overlay` новым режимом/экраном настроек:

```go
type UIPage int

const (
    PageLibrary UIPage = iota
    PageSettings
)
```

Состояние страницы настроек должно включать:

```go
settingsRows   []SettingRow
settingsCursor int
settingsValue  int
settingsEditing bool
```

Существующие `albumsTex` и `tracksTex` постепенно заменить или дополнить общим кэшем текстур панелей. На первом шаге допустимо оставить текущую отрисовку Albums/Tracks и добавить отдельные `settingsLeftTex`/`settingsRightTex`, если это уменьшает риск регрессий. После проверки поведения можно вынести общий renderer.

### Main и конфигурация

`cmd/pmv/main.go` должен получать от Overlay подтверждённое изменение настройки через небольшие методы или событие, например:

```go
changed := overlay.ConfirmSetting()
if changed != nil {
    applyGraphicsSettings(changed, rt, ...)
}
```

Логика применения не должна находиться в C/OpenGL renderer:

- render resolution меняет размеры render target и viewport;
- upscale filter вызывает существующий `RenderTarget.SetNearest`;
- projectM mesh не меняется и остаётся native default `32x24`.

Добавить конфигурационный слой с приоритетом:

```text
CLI flags > settings.json > defaults
```

Предварительная форма файла:

```json
{
  "graphics": {
    "render_width": 320,
    "render_height": 240,
    "upscale_filter": "pixel"
  }
}
```

Файл должен записываться атомарно и переживать отсутствующие или неизвестные поля с откатом к значениям по умолчанию. CLI-флаги остаются полезными для benchmark и диагностики.

## Лёгкий рефакторинг и устранение магических значений

Рефакторинг проводить только в коде, который затрагивается меню настроек или общими панелями.

### Именованные константы

Вынести в один небольшой блок констант значения, которые сейчас зашиты непосредственно в формулах и вызовах отрисовки:

- базовый размер шрифта и базовую высоту экрана;
- коэффициенты высоты нижней панели и отступов;
- прозрачность общего затемнения, фона панели и рамки;
- цвет accent-подсветки, толщину рамки и внутренний отступ строки;
- список допустимых коэффициентов разрешения и порог минимальной стороны.

Имена должны описывать смысл, например `defaultOverlayOpacity`, `panelBackgroundOpacity`, `panelBorderWidth`, `rowPadding`, `renderScaleCandidates`. Не создавать константы для одноразовых очевидных значений, если имя не улучшает понимание.

OpenGL-константы (`GL_LINEAR`, `GL_NEAREST`, `GL_CLAMP_TO_EDGE`) не дублировать в UI-модели. UI использует тип `UpscaleFilter`, а преобразование в OpenGL enum выполняется только на границе renderer.

### Общие layout и панели

Убрать повторение между отрисовкой Albums, Tracks и Settings:

- одна функция вычисляет геометрию верхних панелей и нижней панели;
- одна функция рисует фон панели и рамку фокуса;
- одна функция рисует подсветку активной строки;
- один renderer строит текстовые строки для левой и правой колонок;
- один набор правил задаёт шрифт, отступы, clipping и прокрутку.

Общий renderer не должен знать, что строка означает. Album renderer поставляет строки альбомов, Track renderer — строки треков, Settings renderer — пару `label/value`; выбор трека и применение настройки остаются в соответствующих слоях.

### Разделение ответственности

Разнести ответственность по небольшим границам:

```text
settings model       — типы, defaults, validation
resolution catalog   — вычисление доступных разрешений
settings storage     — JSON load/save и atomic write
settings navigation  — курсор, редактирование, confirm/cancel
overlay renderer     — layout, panels, textures, colors
main/controller      — применение подтверждённых изменений к player/projectM
```

`Overlay` не должен читать `settings.json`, вычислять OpenGL enum или напрямую менять render target. `cmd/pmv/main.go` не должен форматировать строки UI или знать детали текстур панелей.

### Устранение магических индексов и дублированного состояния

- `focusPanel == 0/1/2` заменить именованными константами или типом панели;
- `PageLibrary` и `PageSettings` использовать вместо условных флагов;
- типы настроек и фильтров представить через `const`-значения с проверкой валидности;
- не использовать `2`/`3` как число панелей в формулах без именованной константы или вычисления из layout;
- подтверждённое значение хранить в модели настроек, временное — только в состоянии редактирования;
- для разрешения выбрать один канонический источник: рекомендуется `Width` и `Height`, а масштаб вычислять только при создании render target.

### Управление ресурсами

Сохранить текущую систему кэшируемых OpenGL-текстур, но унифицировать освобождение и инвалидирование:

- каждая панель владеет только своими texture handles;
- изменение данных помечает только затронутую панель dirty;
- изменение размера или шрифта инвалидирует все панели через один метод;
- `Overlay.Close` освобождает ресурсы через общий путь;
- не добавлять отдельные почти одинаковые `deleteTex`/rebuild-последовательности для каждого нового списка.

### Границы рефакторинга

Разрешены изменения в `internal/ui`, типах настроек, конфигурационном хранилище, контроллере применения графических параметров и тестах. Не менять без отдельной причины blur-проходы projectM, mesh, аудиодвижок, общую cgo/OpenGL-архитектуру и старый notification flow.

Если общий компонент нельзя выделить без большого переписывания `overlay.go`, сначала вынести только именованные константы и одну-две функции с очевидным контрактом. Не создавать абстракцию ради формального выполнения SOLID.

## Этапы реализации

### 1. Общая тема и модель настроек

- определить типы `RenderResolution`, `UpscaleFilter` и `GraphicsSettings`;
- определить default-настройки;
- вынести accent color из отрисовки списка;
- добавить вычисление доступных разрешений;
- покрыть вычисление разрешений тестами для `640x480`, `960x540` и ещё одного нестандартного размера.

### 2. Хранение настроек

- добавить пакет конфигурации в актуальную Go-структуру проекта;
- реализовать загрузку `settings.json`;
- реализовать валидацию и значения по умолчанию;
- реализовать сохранение только после подтверждения пользователем;
- проверить приоритет CLI над файлом настроек.

### 3. Переиспользуемый двухпанельный renderer

- выделить общие layout-параметры Albums/Tracks;
- выделить отрисовку фона панели, рамки, курсора, строк и accent color;
- сохранить текущее поведение библиотечного UI;
- добавить режим `PageSettings` с двумя панелями `Label` и `Value`.

### 4. Навигация и применение

- добавить вход в страницу настроек из UI;
- реализовать курсор по строкам;
- реализовать выбор значения и отмену;
- применить resolution без перезапуска, если текущий render target это позволяет;
- применить `Smooth`/`Pixel` через `SetNearest`;
- обеспечить сохранение после подтверждения.

### 5. Тестирование

Проверить:

- список разрешений не показывает дробные размеры;
- сохраняется aspect ratio;
- `640x480` даёт ожидаемый набор вариантов;
- смена разрешения не меняет mesh projectM;
- `Smooth` использует `GL_LINEAR`, `Pixel` — `GL_NEAREST`;
- изменение filter не меняет внутренний blur sampler projectM;
- `Back` отменяет редактирование;
- повторное открытие меню показывает сохранённое значение;
- цвет активного значения совпадает с цветом играющего трека;
- существующие панели альбомов и треков не теряют навигацию.

## Критерии готовности рефакторинга

- в затронутом UI-коде нет повторяющихся RGB/alpha, размеров панелей и коэффициентов layout;
- отсутствуют числовые индексы для выбора панели и страницы;
- Albums, Tracks и Settings используют общий код геометрии, рамки и подсветки;
- модель настроек не зависит от OpenGL и не импортирует UI;
- `main.go` применяет изменения через типизированный результат, а не через разбор строк меню;
- существующие действия библиотеки и текущего трека работают как раньше;
- `go vet`/lint и тесты проходят;
- добавлены тесты для вычисления разрешений, валидации настроек и переходов confirm/cancel;
- `git diff` показывает только изменения, необходимые для меню настроек и локального рефакторинга.

## Что не входит в первый этап

- автоматический `Auto` режим;
- настройка mesh projectM;
- изменение `BlurTexture.cpp` или его `GL_LINEAR`;
- пользовательские веса blur и параметры blur-проходов;
- отдельный advanced-режим с сырыми OpenGL enum names;
- удаление benchmark CLI-флагов.
