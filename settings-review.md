# Review: Settings Implementation

Дата повторного ревью: 2026-07-16

## Результат

Предыдущие замечания исправлены. Повторная проверка показывает, что `MinRenderSide` уже удалена, а политика resize явно зафиксирована в коде. Lint и узкие тесты проходят.

## Уточнение по предыдущему ревью

### Закрыто: `MinRenderSide` удалена

Поиск по `internal/` не находит `MinRenderSide`. Предыдущее замечание об unused-константе было stale reference в отчёте, а не текущей проблемой реализации.

### Закрыто: resize policy зафиксирована

В [cmd/mdpp/main.go](cmd/mdpp/main.go#L686-L698) явно указано, что при resize выбирается ближайшее доступное разрешение по площади. Если сохранённый размер всё ещё доступен, он сохраняется без изменений; поведение не привязывается к transient scale factor.

`TestClosestResolution` покрывает алгоритм выбора ближайшего режима по площади. Отдельного интеграционного теста, который моделирует SDL resize и весь `appLoop`, нет, но для текущей простой политики это остаточный тестовый пробел, а не подтверждённый дефект.

## Исправленные замечания

- Fallback к ближайшему разрешению в `BuildSettingsRows` теперь использует отдельный флаг `found`.
- Частичный `settings.json` больше не сбрасывает отсутствующий `upscale_filter` в zero value: поле декодируется как указатель.
- `SaveSettings` валидирует настройки перед записью.
- Resize окна пересчитывает доступные разрешения и обновляет текущий render size по зафиксированной политике closest-by-area.
- Подсветка Albums/Tracks снова ограничена активной панелью.
- Явный `-render-scale=1.0` отличим от отсутствия CLI-флага через `flag.Visit`.
- `SettingsChanged` удалён, поэтому прежнего несоответствия его контракта больше нет.
